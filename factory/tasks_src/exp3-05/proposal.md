# 任务说明：波特兰收货差异处理（summit-dock-reconciliation）

- **任务标识与版本**　`cua-hard/summit-dock-reconciliation`，v0.1.2。
- **场景**　产业运营 / 收货与应付对账。波特兰主管 Marisol Vega 把 Summit Power Transmission 的到货差异委托给收货员 Alex Morgan。
- **涉及站点**　NetSuite 提供已批准的采购单和累计收货、入账记录。Yahoo Mail 提供供应商的正式发票与发货前文件。Mattermost 提供签收结论、应付处理授权和原线程。
- **输入**　三站种子。**输出**　NetSuite 的部分收货单及同采购单关联的未付供应商账单，以及 Mattermost 原收货线程的回复。

## 主要约束（≥4 类）

1. **跨站匹配**　按供应商、PO4582、波特兰、SPT-L6712 和 SKU 核对。PO4583、SPT-L6702、SPT-97614 是 Reno 的相似记录。
2. **采购授权**　已批准的 Rev B 将皮带从 22 减至 18，已有 8，当前仅可收 10。供应商的采购确认书仍列 Rev A，接受的第 11 条皮带须留待采购处理。
3. **实际收货**　主管签认 11 条皮带、0 个链轮、5 盒链条。承运交接清单上的 14/3/5 包含标签数量和被拒收的损坏箱。
4. **发票范围**　正式发票 SPT-97641 为 14/3/4、833.00 美元。预账单 PB-97641 写 14/3/5、887.00 美元；第 5 盒链条可收货但尚不可入账。
5. **累积数量**　此前已收的两条未入账皮带属于 SPT-L6680 / AP-2691。系统默认建议会把这两条带入本次账单。
6. **保护与交付**　保留采购授权、早期交易和其他订单；原线程记录本次匹配、差异与交易号，付款留待后续。

## 浏览器的必要性

两个关联表单的行选择和数量输入会改变下一步的可入账状态。浏览器可访问完整证据，关闭浏览器调试端点导航。任务使用三站浏览器标签与站点持久化状态。

## 环境复现

- 时钟固定于 2026-11-18 11:30，America/Los_Angeles。三站用各自目录中的完整种子初始化。
- `world.py` 通过 Node 加载仓库中三个 mock 的种子生成器及实际业务转换函数，固定事务时钟及新会话记录 ID 来生成可重放夹具。
- 采购单是收货和账单共同的外键。账单表单按采购单计算累计已收未入账，账单本身无直接指向收货单的外键。

## 安全边界

- 平台运行时仅授权浏览器访问站点；种子和持久化文件属于隔离环境。浏览器配置启用 `hide_browser_debug`。

## 评分方式

见 `rubric.json`。三个权威冲突分别影响库存、应付和原线程的独立检查。按初始及当前状态比较，运行时生成的交易 ID 和时间戳以当前记录为准。夹具得分记录在 rubric，并与独立 verifier 的打包自检核对。
