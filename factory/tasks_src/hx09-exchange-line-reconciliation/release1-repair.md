# Release1 GUI repair

The formal release1 run was valid and scored 0. Every business check failed because the solution had been calibrated on a 1024px preview while the real desktop screenshot is 1280x800. The first Refund click at (848,193) landed on the order contents; the actual control is near (1077,193), so the captured refund-dialog screenshot showed the ordinary order page. Later refund fields, fulfillment, stock controls and split-entry targets consequently missed. The bank row itself did expand because its description spans the old x coordinate, but Add split line is at y678 rather than y698.

The final Calc screenshots exposed a second independent issue: the runtime maximizes the CSV import dialog, whose OK is at (1225,774). The eventual format confirmation is centered on this larger desktop, and Use Text CSV Format is at (806,462). The old final click left that confirmation open, so the output never finished saving.

Only solution/solve.py changed for this repair. It now targets the observed 1280x800 desktop. Main-column gutter focus moved to x912 before Ctrl+Home/End, avoiding text-field caret navigation. Refund and fulfillment modal coordinates, inventory save controls, initial bank split location, and post-tab Confirm coordinates now come from measured 1280x713 content plus the observed 87px toolbar. The tested dynamic keyboard split entry remains unchanged.

Validation: isolated rendered production builds and unmodified production sitehost, reset once from the task seed. `ui-proof/release1-repair-proof.py` measured the actual controls at the corrected viewport. `release1-coordinate-replay.py` imports the repaired solve.py and executes its browser business functions using only fixed mouse coordinates and keyboard. Its only adaptation is page.goto for address navigation, because headless Chromium has no address bar. No business operation uses selectors or DOM state writes. The resulting native records plus the previously GUI-exported Calc CSV score 1.0 in `release1-coordinate-verifier.json`; screenshots use `coordinate-*`. The new Calc coordinates are checked against actual formal screenshots, with native full desktop replay left to the coordinator. Python compilation passes.
